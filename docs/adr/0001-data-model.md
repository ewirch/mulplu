# Data model: per-item state plus three global fields

The entire persistent state of the app is 36 per-item records plus three global fields. Per item, keyed by the unordered factor pair: `level` (1–5), `lastCountedOn` (LocalDate — has today's counting answer happened?), `satisfiedOn` (LocalDate — answered correctly today, for the day goal), `hasEverConsolidated` (Bool — pool membership / admission), and `lastPromotedOn` (LocalDate — the *promoted today* map overlay marks any level-up that day, which is not derivable from the other fields, so every level-up stamps this date). Globally: `calibrationIndex` (0–36; 36 = calibration complete — probe order is the admission order, so one index replaces a per-item flag), `calibrationMissStreak` (persisted so closing the app cannot reset the mercy stop's 6-in-a-row counter), and `wasEverCompleted` (the permanent completion mark). Everything else — pool membership, learning front, map tile states — is derived at read time, never stored (issues #5, #7, #10).
