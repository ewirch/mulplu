# No session: the day is the only unit

There is no session in the product. A go has no length of its own — no item count, no wall clock, no stop-at-first-mistake — and therefore nothing is resumable, counted partially or discarded: state is per item plus a date, and leaving is always free. The day's work is defined entirely by the **day goal** (every pool item answered correctly at least once today), which is also its only edge: reaching it is a hard stop, and there is exactly one mode — no free-practice mode alongside it. Any session bound would make progress depend on how long the child plays, which the selection design (#5) rejected; and past the day goal, with timing gone (#2), correctness is the only recorded quantity and every pool item is already correct — practice beyond it moves nothing the app could ever show. Calibration is the sole exception: a fixed 36-probe pass with its own resume rule, where a defined end makes chunking harmless.

Hard to reverse because most of the app's shape is downstream of it: no resume state, no session summary screen, no second ending state ("day over, goal not met"), no interruption handling beyond "the open question evaporates". Surprising because practically every drilling app is session-shaped. The trade-off, accepted knowingly: the worst day is a long one (~90 questions measured in simulation, #13) with no in-app mercy exit — the exit is closing the app, free and without loss (issues #8, #5, #13).
